# 한양도감(漢陽都監) — 독자 백오피스 설계

이름은 조선의 임시 관청 ‘도감(都監)’에서 땄다. 한 사업을 맡아 세우고 관리하던 관청이며, ‘한양을 그린 도감(圖鑑)’으로도 읽힌다. 화면 제목과 로그인에 한자 병기. 작성: 2026-09-22. Django 관리 화면(`/backoffice/`)은 모델 단위 편집 도구로 남기고, 한양3D 운영에 맞춘 화면을 `/office/`에 모듈별로 덧붙인다. 각 모듈이 충분해지면 그 영역의 편집 링크를 관리 화면에서 사무실로 옮긴다.

## 원칙

- **서버 렌더링, 의존성 없음.** Django 템플릿과 기본 CSS만 쓴다. 지도 미리보기처럼 꼭 필요한 곳에만 작은 JS를 붙인다. 프런트엔드 빌드 도구를 들이지 않는다.
- **읽기는 넓게, 쓰기는 좁게.** 목록·상세는 staff 누구나 본다. 쓰기는 기능마다 Django 모델 권한(`webapp.change_item` 등)을 요구하고, 하나의 작은 폼으로 처리하며, `LogEntry`에 남겨 관리 화면의 변경 이력과 한곳에 모은다. 되돌릴 수 없는 작업(초기화·삭제)은 확인 단계와 사유 입력을 둔다.
- **플레이어 자료 보호.** 비밀번호 해시·토큰은 화면에 내지 않는다. 검색은 이름만. 내보내기는 계정을 제외한 콘텐츠만 허용한다(`export_content`).
- **운영 정본은 DB.** 콘텐츠(건물·이야기·물건)는 DB가 정본이고 Git JSON은 동기화 원천이다. 이벤트 정의는 아직 Git 파일이 정본이며, DB로 옮길 때는 장면 데이터(`SceneDataset`)와 같은 방식(최초 등록·검증·해시 충돌 검사·백업)을 따른다.
- **접근.** `/office/login/`은 관리 화면과 같은 Nginx 요청 제한을 받는다. staff가 아닌 계정은 403. 세션·CSRF는 Django 기본.

## 구조

```
webapp/office/            access.py(권한 데코레이터) · urls.py · views.py
webapp/templates/office/  base.html(좌측 모듈 내비) · login · dashboard · players · player · buildings · items · events · event
webapp/templatetags/office.py
webapp/test_office.py
```

모듈은 `views.MODULES` 목록에 등록하면 내비게이션에 나타난다. 새 모듈은 `views.py`에 뷰를, `templates/office/`에 템플릿을, 필요하면 권한 이름을 더한다.

| 모듈 | 지금(1단계) | 다음 |

| 대시보드 | 계정·활동·거래·유통 엽전·건물·이야기·물건·장면 데이터 수, 이벤트 진행 집계, 콘텐츠 원본·마지막 가져오기, 최근 거래·계정 | 일·주 활동 추이 그래프(서버 집계, SVG), 배포 버전·health·백업 최신 시각, 멀티플레이 접속 수 |

| 건물 | 시대·이름·ID 검색, 모형·이야기 수·공개 여부, 관리 화면 편집 링크 | 원도 픽셀·시대·크기·모형 매개변수 편집기와 지도 위 미리보기, 출처·상세 설명 편집, 공개 전 검증(위치·모형 생성기·설명 연결), 이야기 편집 |
| 물건·가격 | 목록(단위·값·가게·쓰임·플레이어 보유), **값 수정**(권한·LogEntry) | 이름·설명·아이콘·쓰임·최대 보유 편집, 가게별 진열 편집, 되사기 비율(지갑 설정) 편집, 가격 변경 이력 표 |
| 이벤트(퀘스트) | 정의 목록(버전·확인 지점·꾸러미·검증 결과·진행 집계), 상세(단계 표·JSON·출처·진행 50건) | `EventDefinition` 모델로 DB 저장(초안/공개, 버전, 검증, 파일에서 최초 등록), 단계 편집기(talk·talks·module 폼, 원도 픽셀 선택기), 공개 시 `version` 증가 안내, 진행 초기화 |

## 이벤트 정의의 DB 이전(설계)

`EventDefinition(slug, data JSON, version, status draft/published, updated_at, updated_by)`. 서버 `events.definitions()`는 DB 모드에서 공개된 행을 우선하고 없으면 파일을 읽는다(장면 데이터와 같은 규칙). 편집은 초안에만 하고, 공개 시 `validate()`를 통과해야 하며 단계 구조가 바뀌면 `version`을 올리도록 강제한다(기존 진행은 처음부터). 파일과 DB의 차이는 `sync`처럼 미리보기 후 적용한다. 모듈 코드(`events/*.js`)는 여전히 배포로만 바뀐다.

## 확인

`webapp/test_office.py`: 익명은 로그인으로, staff 아닌 사용자는 403, staff는 모든 페이지 200, 권한 없는 값 수정 403, 값 수정 시 검증과 LogEntry. 브라우저 확인은 임시 DB·superuser로 `/office/` 화면을 렌더해 본다.
