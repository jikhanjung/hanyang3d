# 243 — 아관파천 첫 회상 체험과 계정 액션바

## 회상

1907년 러시아공사관 문지기 대화에 ‘1896년 가마 행렬을 따라가 보겠습니다’를 추가했다. `/events/agwanpacheon/`는 1907년과 별도 화면이며 Colyseus에 접속하지 않는다. 영추문 → 궁궐 서쪽 → 내수사 방면 → 새문고개 방면 → 정동 → 러시아공사관 앞의 추정 경로 약 1.33km를 따라 두 가마가 움직인다. 가마꾼 8명과 메는 막대·가림막·보행 동작을 자체 모형으로 표현했다.

- 가마 속도 1.65m/s, 두 가마 간격 9m. 플레이어가 너무 가깝거나 45m 이상 뒤처지면 대기하며 가마 뒤로 돌아가기 지원.
- 통과할 수 있는 지면·충돌을 검사하고 막힌 부분은 짧은 우회 경로를 탐색한다. 길을 못 찾으면 건물을 통과시키는 대신 시작 오류를 표시한다.
- 전차·후대 건물·1907년 NPC·상점·민가를 숨긴 제한된 회상 배경이다. 확인 대상으로 선별한 기존 건물 모형 일부만 사용한다. 1896년 도시 전체 복원은 아니다.
- 1907년 지도·현대 고도를 소급 참고했다는 사실과 가마 수·세부 경로·인물·대사의 창작 범위를 화면 출처 설명에 명시했다. 원도 지도는 길찾기 참고로 남는다.
- 마지막 확인 지점, 진행 상태, 최초 완료 시각은 계정별 `EventProgress`에 저장. 중단·재접속·재관람 지원. 경제 보상 없음. 클라이언트 이동을 서버가 권위적으로 검증하는 퀘스트 보상 시스템으로 주장하지 않는다.
- 문지기에서 시작하면 기존 1907년 위치를 기존 보행 저장에 남기고, 돌아왔을 때 동일 계정의 위치·승마 상태를 복원한다. 직접 회상 주소로 들어온 경우 기존 복귀 예약은 없다.
- P02의 전체 밀서·답사·검문 6단계는 후속 범위다. 이번에는 출발·따라가기·도착 해설·복귀를 연결했다.

## 액션바

기존 `hanyang3d-actions:<계정명>` localStorage 저장을 서버 `Player.action_bar`로 이전했다. 1750·1907년 공통 `shop.js` 변경이다.

- 계정별 10칸과 수정 번호를 저장하고 다른 PC 로그인 시 로드한다.
- 서버 값이 null인 경우에만 현재 브라우저의 기존 배치를 자동 가져온다. 빈 배열 10칸은 의도적으로 비운 배치로 구분하여 오래된 PC가 되살리지 않는다.
- 수정 번호 비교로 동시 편집 충돌을 감지하며 오래된 화면의 무조건 덮어쓰기를 막는다. 저장 실패·충돌은 화면에 알린다.
- 슬롯은 아이템 참조일 뿐 인벤토리 복제가 아니다. 서버에서 사용 가능한 아이템 ID·칸 수·로그인·CSRF를 검사한다.
- 기존 설정이 있는 PC에서 최초 한 번 접속해야 그 PC의 localStorage를 가져올 수 있다. 서버가 다른 PC의 브라우저 저장소를 원격으로 읽지는 못한다.

## 검증과 배포 조건

- Django 기능 검사: 인증·정의 버전·확인 지점 순서·완료 중복·재시작, 액션바 별도 브라우저 계정·빈 배치·충돌·잘못된 입력·CSRF.
- Playwright: 회상 시작, 669개 경로점 생성, 전차·멀티플레이 분리, 중단·재개, 전체 경로 진행과 완료 기록, 별도 브라우저의 액션바 복원.
- migration 0012(회상 진행), 0013(액션바) 필요. 일반 콘텐츠 export에는 사용자 진행을 포함하지 않고 운영 DB 백업으로 보존한다.
- 데이터·프런트엔드·백엔드가 함께 필요한 기능이므로 새 웹 이미지 배포 필요. 멀티플레이 코드는 변경 없음.
