# 088 — 로딩 개선 후속: 꼭짓점 공유, 미리 계산한 하천 지형, 브라우저 캐시

087에서 남겨 둔 세 가지를 모두 적용했다.

## 1. 하천 지형 꼭짓점 공유

- 세분화 결과는 삼각형마다 꼭짓점 셋을 따로 가져 121만 개였다. `ChannelTerrain.weld`가 위치가 정확히 같은 꼭짓점을 하나로 합친다. 공유 변의 중점은 같은 두 끝점에서 계산되므로 값이 정확히 같다.
- 꼭짓점 121만 → 20만 개. 삼각형 꼭짓점 위치는 그대로(단위 검사로 확인)라 건물·성벽·주택 바닥 높이가 운영판과 모두 같다.
- 달라진 것은 법선뿐이다. 삼각형마다 따로 계산하던 각진 음영이 이웃 삼각형과 이어져 매끄러워졌다. 같은 자리 화면을 견주어 보면 왼쪽 아래의 옅은 면 자국이 사라진 정도다. 세분화 전 원래 지형 격자는 원래 매끄러운 음영이었다.

## 2. 미리 계산한 하천 지형 파일

- `scripts/terrain/build_channel_refined.py`가 로컬 서버를 워커만 쓰는 모드(`?refine-cache=off&refine-export=1`)로 띄워, 브라우저 워커가 만든 결과를 그대로 `gis/georeferenced/terrain3d/channel_refined.bin.gz`에 쓴다. 원본 12.2 MB, gzip 5.2 MB. 다른 `gis/georeferenced` 파일처럼 Git이 아니라 데이터 묶음으로 배포한다.
- 파일 머리에 입력 열쇠를 넣었다. 지형 격자 위치·UV·색·색인, 하천 경로, 알고리즘 이름을 해시한 값이다. 페이지는 자기 입력으로 같은 열쇠를 계산해 일치할 때만 파일을 쓴다. 지형·보정점·물길이 바뀌거나 브라우저 엔진의 수학 함수가 끝자리까지 같지 않으면 조용히 워커로 계산한다.
- 파기 거리값(`matches`)은 파기가 닿는 꼭짓점만 담고 나머지는 무한대로 되살려, 워커 결과와 같다.
- 파일을 내려받는 동안 워커도 함께 돌려 먼저 끝난 쪽을 쓴다. 파일이 이기면 워커를 끝내고, 워커가 이기면 내려받기를 멈춘다.
- 서버는 이 파일을 `Content-Encoding: gzip`으로 보내 브라우저가 풀게 한다.

## 3. 브라우저 캐시

- 3D 페이지의 스크립트는 `/v/<버전>/webapp/static/...` 경로로 부른다. 모듈 안의 상대 경로 import와 워커(`new URL(..., import.meta.url)`), 자료 fetch(`asset()`)가 같은 버전 경로를 따른다.
- 서버는 실행 중인 버전과 같은 `/v/<버전>/` 요청에 `Cache-Control: public, max-age=31536000, immutable`을 준다. 다른 버전 경로는 버전 없는 주소로 돌려보낸다.
- 모든 자원에 `ETag`·`Last-Modified`를 붙이고, `If-None-Match`가 맞으면 304로 답한다. 버전 없는 주소는 이전처럼 `no-cache`다.
- 개발 중 버전을 올리지 않고 파일을 고치면 같은 브라우저에서 옛 파일이 남을 수 있다. 새 창(시크릿) 또는 버전 올림으로 피한다.

## 유지 관리

지형 격자, 보정점, 물길 판독, `channel_terrain.js`의 세분화가 바뀌면 `scripts/terrain/build_channel_refined.py`를 다시 돌린다. 안 돌려도 열쇠가 달라져 워커로 계산하므로 틀린 지형이 나오지는 않는다. `terrainLoading.refine.source`가 `file`인지로 확인한다.
