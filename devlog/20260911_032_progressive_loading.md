# 032 — 단계별 화면 표시

2026-09-11. 모든 요소 계산이 끝날 때까지 캔버스가 비어 있던 로딩 방식을 변경했다.

## 표시 순서

1. HTML의 캔버스 영역에 준비 안내와 단계 진행 표시
2. DEM 지형을 먼저 표시
3. 도성대지도 오버레이 표시
4. 주요 건물·문·이름 표시
5. 물길 표시와 하천 주변 지형 계산
6. 보정 지형·성벽·길 표시
7. 일반 주택·상가 배치
8. 보행 모형 표시 후 전체 조작 활성화

각 단계에서 실제 프레임을 그린 뒤 브라우저가 화면을 표시할 시간을 준다. 지형이 나온 뒤부터 회전·확대가 가능하며, 로딩 도중 사용자가 바꾼 시점은 이후 단계에서 초기화하지 않는다. 아직 준비되지 않은 레이어의 도구는 로딩 완료까지 비활성화한다.

## 무거운 계산과 오류 처리

하천 주변 삼각형 세분화와 하도 최근접 계산을 `terrain_worker.js`에서 실행한다. 주 스레드는 이미 준비된 장면을 유지하고 로딩 단계나 시점이 바뀔 때 다시 그린다. 로딩 완료 후에는 기존처럼 연속 렌더링으로 보행을 재생한다. 결과는 위치·인덱스·UV·색상·하도 대응값의 TypedArray를 전송한다. 하도 대응값은 거리·수면·폭 순서로 압축 저장하며 동일한 절삭 계산에 사용한다.

주택과 보행자 생성은 보정 지형·성벽이 표시된 이후로 옮겼다. 전체 계산량을 없앤 것은 아니며, 후반 건물 접지·GPU 업로드 단계의 짧은 지연은 남을 수 있다. 빈 화면으로 전체 계산이 끝나기를 기다리는 동작을 해소하는 변경이다.

요청이나 계산이 실패해도 기존 장면을 지우지 않는다. 캔버스 위에 중단 상태와 다시 불러오기 버튼을 표시한다. 실패 후 전체 준비 완료로 표시하지 않는다.

## 검증

`check_progressive_browser.py`는 원도 응답을 보류한 상태에서 지형 표시와 회전을 확인하고, 주택 응답을 보류해 주택 없이 지도·길·성벽이 먼저 보이는지 검사한다. 이후 단계 순서, 최종 지형 정점 수·절삭값·건물 수·보행자 수와 보정 해제 원상 복원을 확인한다. 원도 요청을 강제로 실패시키는 경우에도 지형과 재시도 버튼이 남는지 검사한다.
