# 194 — 명동성당 내부 보행 성능 측정과 개선

v0.5.20 배포 후 사용자가 성당 내부 보행 시 느려짐을 보고했다. 프레임을 1인칭 갱신·이름표 가림 판정·렌더로 나누어 측정했다.

## 측정

`scripts/terrain/measure_1907_cathedral_perf.py`는 임시 DB·임시 계정으로 1인칭에 들어가 성당 앞 거리와 성당 내부에서 각 단계를 60프레임씩 반복해 프레임당 밀리초를 출력한다. 헤드리스 Chromium(Vulkan) 개발 PC 기준이며 GPU 시간은 대표성이 없다.

| 위치 | 단계 | 개선 전 | 개선 후 |
| --- | --- | --- | --- |
| 내부 PC 1100×800 | 이름표 가림 판정 (38개) | 246 ms | 0.3 ms |
| 내부 모바일 390×844 | 이름표 가림 판정 (28개) | 174 ms | 0.2 ms |
| 내부 | 1인칭 갱신 (카메라 벽 충돌) | 1.8 ms | 0.1 ms |
| 외부 | 이름표 가림 판정 (80개) | 6.1 ms | 1.9 ms |
| 내부 | 렌더 (CPU 제출) | 1.1 ms | 1.2 ms |

## 원인

- 화면 안의 건물 이름표마다 카메라에서 이름표까지 광선을 쏘아 다른 건물에 가려지는지 판정한다. 성당 내부에서는 모든 광선이 성당 경계 상자를 지나므로 이름표 하나마다 세부 모형 삼각형 7만 5천 개를 전부 검사했고, 이름표 30여 개에 약 250 ms가 들어 4 fps 수준이 됐다.
- 보행 카메라의 벽 충돌 광선도 재질별로 병합한 외피 메시 전체를 검사했다.
- 렌더 자체는 문제가 아니다. 삼각형·드로우콜은 실외보다 오히려 적다.

## 개선

- 이름표 가림 판정은 각 건물의 원거리 LOD 실루엣(`lod.proxy`)에 광선을 쏜다. 실루엣은 이미 모든 건물에 있으며 보이지 않을 때도 판정에만 쓴다. 실루엣이 없는 건물은 이전대로 모형 전체를 검사한다. 성당 내부에서는 실루엣 상자에 막혀 바깥 건물 이름표가 숨는데, 벽 안에서 보이지 않아야 할 이름표이므로 의도한 결과다. 열린 정문으로 보이는 바깥 이름표는 숨겨진다.
- 성당 카메라 벽 충돌은 병합 전 벽·기둥·창 부품을 숨긴 그룹에 보존해 검사한다. 부품마다 경계 구가 있어 광선 근처의 몇 개만 삼각형까지 검사한다. 그리는 메시는 그대로 23개이며 장면 삼각형 수도 변하지 않는다.

## 검증

`check_1907_cathedral_browser.py`(입장·퇴장 보행, 카메라 벽 충돌, LOD, 메시 수), `check_1907_trams_browser.py`(이름표 가림 판정 포함), `check_1907_stairs_browser.py`, Django 테스트 64개 통과. 메시 수 검사는 숨긴 충돌 그룹을 제외하도록 갱신했다.
