# 119 — 운영 콘텐츠 DB 전환과 백업 연결

## 범위

기록 118의 프레임워크를 운영으로 전환한다. 관리자 ID는 사용자 요청대로 `admin`이다. 웹은 v0.3.0, 멀티플레이는 v0.2.4를 유지한다.

## 구현

- `MULTIPLAYER_IMAGE_TAG`를 웹 `IMAGE_TAG`에서 분리하고, `--web-only` 빌드는 웹과 데이터 묶음만 만든다. 현재 공간 호환 키 `v0.2.4`를 웹 버전과 분리해 기존 브라우저와 같은 공간을 사용한다.
- DB 모드 배포는 웹 중지 → 기존 DB의 검증 백업 → 일회용 컨테이너 migration/최초 가져오기 → 서비스 확인 순서다. 재가져오기는 기존 편집 데이터를 바꾸지 않는다.
- 별도 콘텐츠 볼륨과 HTTPS 관리자 쿠키를 사용한다. 비밀키·기존 환경 설정은 보존한다.
- 시간별 스냅샷과 서비스 설정을 읽기 전용 SSH export 도구로 내보낸다. 최신성·무결성·외래 키·세션 제거 여부를 확인한 사본만 전송한다.
- 개발 호스트의 실행본은 `system-operation/m710q/backup-hanyang3d.py`에 둔다. 로컬 일간 30일·NAS 90일 이후 월초 보존, 잘못된 사본 미채택, 임시 파일 뒤 원자적 교체를 사용한다. 메시지 전송 기능은 추가하지 않는다.

## 검증 및 운영 기록

로컬 검사와 실제 운영 전환·복원 연습·백업 스케줄 설치 결과는 완료 후 이어서 기록한다.
