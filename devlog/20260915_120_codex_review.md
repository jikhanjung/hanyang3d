# 120 — Codex 작업(111~119) 검토와 수정 계획

사용자 요청: Codex가 한 작업(`cee8d2b..0f6e247`, 13커밋·96파일·약 4,500줄, 운영 v0.3.0)을 확인하고, 결과를 기록한 뒤 고치기.

## 확인 방법

- 로컬: `manage.py test` 27개, `makemigrations --check`, `multiplayer` 방 테스트, `deploy/test_release_env.py` 모두 통과.
- 운영: `/healthz`는 v0.3.0, 콘텐츠 원천 database(건물 103·이야기 33), 백업 실패 없음. `/backoffice/login/`이 공개로 열리고 HSTS 헤더가 없는 것을 확인했다.
- 세 갈래 읽기 전용 검토: 함께 걷기(서버·클라이언트·배포), 콘텐츠 DB·백오피스, 117의 새 이야기 4건 실록 대조.

## 발견

### 함께 걷기

1. [높음] 매치메이킹 HTTP 요청만으로 방을 무제한 만들 수 있다. `mapVersion`을 서버가 검사하지 않고 `onAuth`는 WebSocket 연결 때에야 돈다. 방마다 NPC 130명 틱이 돌아 단일 프로세스를 포화시킬 수 있다(코드 판독, 재현 안 함).
2. [중간] 좌석 예약 반복으로 방을 채워 정상 사용자를 흩어 놓을 수 있다.
3. [중간] `chat-history` 요청에 빈도 제한이 없어 연결 하나로 큰 송신을 일으킬 수 있다.
4. [중간] nginx `/multiplayer/`가 클라이언트 IP를 넘기지 않고 요청·연결 수 제한이 없다.
5. [낮음] 서버 다운·끊김 뒤 1인칭이 남고 버튼은 원래대로 돌아가 버튼으로 나올 수 없다.
6. [낮음] 닮은 문자로 이름 흉내, ZWJ 이모지 거절, 헬스체크의 NPC 수 130 고정, 월드 버전 두 곳 기재.

견고한 점: 이름·채팅은 textContent·캔버스로 그려 XSS 경로가 없고, 위치 검증·`maxPayload`·초당 30회 제한은 실제로 동작한다. 서버는 127.0.0.1 바인드·비루트·읽기 전용 컨테이너.

### 콘텐츠 DB·백오피스

1. [높음] `import_content`는 최초 한 번만 돌아, 이후 Git의 JSON(`1750_landmarks.json`, `doseong_stories.json`) 수정이 운영 DB에 반영될 길이 없다. 테스트·브라우저 검사는 JSON을 보므로 통과하고 운영은 그대로다.
2. [높음] DB의 모형 이름·다리 id·동네 이름이 새 이미지와 어긋나면 `/`가 500인데, 배포 검사는 건수만 세는 `/healthz`만 본다.
3. [중간] `/backoffice/`가 인터넷에 열려 있고 로그인 시도 제한·IP 제한이 없으며 관리자 ID가 문서에 적혀 있다.
4. [중간] SECRET_KEY가 없거나 예시값이어도 시작한다. 없으면 워커마다 무작위 키가 생긴다.
5. [중간] DB 모드 설정이 남은 채 v0.2.4로 되돌리면 옛 이미지로 migrate·import를 시도해 실패한다(코드 추론).
6. [중간] 백업이 한 번 실패하면 Docker healthcheck가 unhealthy가 되어 급한 수정 배포까지 되돌려진다.
7. [낮음] 오프사이트 묶음에 SECRET_KEY·비밀번호 해시 포함, 배포 전 스냅샷 누적, HSTS 없음.

견고한 점: CSRF·프록시 헤더, 업로드 경로 없음, 안내 Markdown 출력 escape, 트랜잭션 가져오기, `migrate --check` 거부, online backup·무결성 검증·원자적 채택.

### 새 이야기 4건(117)

틀린 사실 없음. 다듬을 곳: 종묘 대리청정 이유 표현, 홍화문 이야기의 균역법 연결 출처 추가(영조 26년 7월 2일), 흥인문 이야기에 준천 맥락 출처 추가(영조 36년 2월 19일). 자료집 각주 59와 H21도 같은 보완.

## 수정 순서

1. 보안: 함께 걷기 과부하 차단(방 생성 조건 검사·방 수 상한·채팅 기록 1회·nginx 제한과 IP 전달), 백오피스 로그인 제한과 nginx 제한, HSTS, 문서의 관리자 ID 제거.
2. 운영: 배포 검사가 실제 페이지 렌더링을 확인, SECRET_KEY 강제, 백업 실패 시 healthcheck 완화, 되돌리기 안전장치, 1인칭 끊김 처리.
