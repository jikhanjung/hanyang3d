# 019 — 원도 진입로와 성문 통로 방향

2026-09-10

## 요청과 결과

도성대지도의 길이 성문 통로로 이어지도록 광화문·흥인지문·숭례문·돈의문의 방향을 조정했다. 모든 문이 남북을 향하던 상태에서, 원도 주변 진입로를 판독하고 기존 5점 TPS를 적용한 축에 통로를 맞췄다. 흥인지문은 남북 축에서 약 90.95° 회전해 동서로 통과한다. 광화문은 약 -0.006°, 숭례문은 117.58°, 돈의문은 후속 위치 교정과 함께 교차점 주변의 길로 방향을 다시 구한다. 이는 Three.js +z(남쪽) 기준 회전각이며 역사적 실측 방위각이 아니다.

`gis/buildings/1750_landmarks.json`에 원본 식별자·SHA-256·판독 픽셀 두 점·방법을 기록했다. 흥인지문 옹성 바깥의 꺾이는 길 대신 문 서쪽의 직선 진입로를 사용했다. 사용자가 돈의문의 위치가 성벽보다 서쪽이라고 지적해, 문 모형을 성벽·길 교차점인 원도 (766, 1481)로 옮겼다. 진입로 축도 (741, 1483) → (796, 1478)로 수정했다. 모형 좌표는 실제 표시 원도 삼각형을 보간하며 TPS 입력과 파란 보정점 (703, 1493)은 유지한다. 기존 현대 위경도는 modern_reference로 보존했다. 자세한 좌표는 `docs/doseong_terrain3d.md`에 정리했다.

문 모형·선택 박스·받침을 함께 회전한다. `ground_support.js`가 지형 삼각형을 회전한 바닥 좌표계로 변환하여 절단하도록 확장했다. 초기 배치와 하도 보정 재계산 모두 같은 방향으로 바닥 높이를 구한다.

## 검증

- `node scripts/terrain/test_ground_support.cjs`: 기존 경사면·능선·원도 오프셋 및 회전한 직사각형의 정확한 높이 범위 통과.
- `.venv/bin/python manage.py test webapp`: 7개 통과.
- 브라우저: 네 문의 TPS 진입로 방향과 통로 축 일치, 흥인지문 동서 축, 받침 회전 일치, 실제 석축의 열린 통로 및 벽체 광선 검사 통과.
- 초기 브라우저 전체 실행에서는 다리 클릭 검사가 실패했다. 확대·선택 해제 버튼이 페이지를 스크롤한 상태에서 선택 정보 영역의 높이가 바뀌어 투영 좌표가 어긋나는 상황을 확인했다. 대상 좌표를 구하기 전에 페이지 상단으로 스크롤하고 화면 갱신을 기다리도록 검사를 보완했다.

원본 지도·DEM·기존 위치 보정점은 변경하지 않았다. 012 이후 누적 작업과 함께 아직 미커밋 상태다.

후속 검증은 `scripts/terrain/check_gate_orientation_browser.py`로 네 문의 방향·석축·돈의문 이동·하도 보정 전환·높이 강조 시 받침을 직접 확인한다.

후속 020에서 사용자 지적에 따라 돈의문 보정점 자체도 수정했으며, 이 기록의 모형·보정점 분리 상태는 현재 기준이 아니다.
