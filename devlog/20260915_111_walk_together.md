# 111 — Colyseus로 접속자끼리 함께 걷기

후속 [112 — NPC 동기화와 이름 입력](20260915_112_shared_npcs_player_names.md)에서 이 기록의 NPC 독립 재생 제한을 보완했다.

사용자가 한양3D의 걷기를 멀티플레이로 확장하고 싶다고 했고, 첫 범위로 ‘다른 접속자와 함께 걷기’를 선택했다.

## 구현

- 별도 Node.js/Colyseus 프로세스: 공간당 최대 32명, 초당 10회 위치·방향 배포. 지도 앱 버전별 공간 분리. 위치의 숫자·범위 검사와 메시지 빈도 제한.
- 지도 설정의 ‘함께 걷기’ 버튼, 접속 인원, 연결 실패/종료 안내. 청록색 옷과 나그네 이름표로 다른 접속자를 구분. 위치·방향 보간과 기존 지면 높이 계산 사용.
- 전체 지도 복귀·명시적 나가기·탭 닫기 시 퇴장. 연결 중 취소와 재접속 처리, 다른 캐릭터의 GPU 자원 정리.
- Colyseus SDK 0.18.2를 로컬 정적 자원으로 보존하고 MIT 라이선스·출처 페이지 표시. npm 의존성과 잠금 파일, 실행·운영 연결 문서 추가.

## 확인

- Django 기존 검사 15개 통과.
- Node 입력 검증 검사 통과.
- 실제 서버 연결 검사: 같은 공간 입장, 이동 전달, 잘못된 입력 무시, ID 위조 방지, 지도 버전 분리, 퇴장 반영 통과.
- 독립 브라우저 세션 2개: 접속 인원, 다른 캐릭터 생성, 위치·방향 갱신, 전체 지도 복귀, 재접속, 탭 닫기 반영 통과. 브라우저 JavaScript 오류 없음.
- 최초 브라우저 검사는 두 지도의 지속 렌더링으로 소프트웨어 GPU에서 시간 초과했다. 검사에서 지도 로드 후 반복 렌더링만 생략하고 애니메이션 루프·이동·네트워크 처리는 유지해 재검증했다. 실제 프레임률이나 부하 수용량을 검증한 것은 아니다.
- JS 구문 검사와 `git diff --check` 통과.

## 제한과 후속

이 단계는 접속자 표시 프로토타입이다. 이동·지형 충돌은 클라이언트가 계산하며 NPC도 각 브라우저에서 독립적으로 이동/회피한다. 따라서 NPC 위치와 길이 막히는 상황이 서로 다를 수 있다. 다음에는 NPC에 고정 ID를 부여하고 경로·회피·충돌의 권위 있는 계산을 서버로 옮겨야 한다. 브라우저의 InstancedMesh와 보행 애니메이션은 유지할 수 있다.

사용자는 음성 부하를 고려해 디스코드 사용과 문자채팅을 논의했다. 문자채팅은 기존 Colyseus 연결에 추가 가능하지만 이번에는 채팅이나 디스코드 링크를 구현하지 않았다.

운영 배포는 수행하지 않았다. 검증용 Django는 기존 18014 서버를 유지하고 18015에서, Colyseus는 2567에서 실행했다. [실행·환경변수·프록시 설정](../multiplayer/README.md).
