# 214 — 청계천 낚시·산약초 채집·1907년 화강암과 수목

## 구현

1750·1907년의 공통 봇짐·상점·액션바에 낚시와 약초 채집을 연결했다. 청계천 광통교 옆 낚시꾼은 강태공 고사를 이야기하고 낚싯대(15문)를 판다. 낚싯대 쓰기로 줄을 드리워 18~30초 기다리며, 15% 확률로 얻은 민물고기는 기존 내어물전을 포함한 상점에 판다. PC 액션바 숫자 키와 모바일 봇짐 쓰기 버튼을 모두 사용한다. 이동·점프·승마·종료·재사용은 낚시를 취소한다.

북악산·인왕산·남산에는 1750년 수목 자료에서 고정 선택한 후보 63곳 중 지형 고도 100m 이상인 39곳에 단순한 약초를 놓았다. 두 시대 공통으로 1인칭에서 가까이 다가가면 손 모양 커서를 표시하고 우클릭으로 채집한다. 성공률은 80%, 같은 자리의 재시도 대기는 5분이다. 종루/보신각 근처에 ‘약전 藥廛’ 표지와 창작 약재상을 놓고 산약초 판매를 연결했다. 생물종·약효·실제 점포나 특정 인물을 고증한 표현은 아니다.

1907년에도 1750년의 화강암 재질 함수, 수목 모형·분포와 주변 녹색 지면을 재사용한다. 1750년의 원도 픽셀을 동일한 TPS·산지 보정과 지리 좌표로 옮긴 뒤 1907년 지면에 얹는다. 해당 시대 건물·민가·물길·성벽에 겹치는 나무와 암반의 나무 일부를 제외해 현재 2,206그루가 배치된다. 설정에 나무·숲, 화강암 질감 체크박스를 추가했다.

자료·조작·가격·확률·고증 한계는 [낚시·약초 문서](../docs/fishing_and_herbs.md)에 정리했다. 대화창에도 우리역사넷·국사관논총·한국민족문화대백과 출처를 넣었다.

## 데이터와 지급 검증

- `FishingCast`: 계정당 진행 중 낚시 하나, 서버 시각·만료·서버 확률·낚싯대 보유 검사. 완료 응답 재시도 시 중복 지급 방지.
- `HerbHarvest`: 계정·후보 ID별 고유 재채집 기록. 시대 변경·새로고침과 상관없이 대기 유지.
- 두 지급 경로 모두 트랜잭션 첫 단계에서 Player 행 쓰기 잠금을 획득해 SQLite에서도 같은 계정의 지급을 직렬화한다.
- 기존 거래 API를 그대로 사용해 물고기·약초 판매 대금과 봇짐 차감을 기록한다.
- 서버가 지형·실시간 좌표를 시뮬레이션하지는 않는다. 근거리·물가 방향·화면 선택 검사는 클라이언트에서 한다. 보상 확률·대기·수량을 클라이언트가 지정할 수는 없다.

## 검증

Django 전체 79개 테스트가 통과했다.

- 서버 검사: 로그인·CSRF·낚싯대 필요, 조기 회수 거부, 중복 시작의 같은 토큰, 중복 완료 지급 방지, 실패 확률 경계, 취소·만료, 다른 계정 토큰 거부, 약초 확률 경계·재채집·계정별 분리, 판매 후 재판매 거부, 카탈로그 추가 시 기존 가격·봇짐 보존.
- `scripts/terrain/check_fishing_herbs_browser.py`: 두 시대 장면 로드, NPC·약재상과 39개 약초, 낚싯대 구매·PC 액션바 1키 시작·실제 서버 대기 결과·모바일 쓰기·이동 취소, 손 커서·실제 우클릭 채집과 재채집 기록, 1907년 수목·암반 재질과 설정 확인.
- 낚시·약초 및 1907년 자연 화면 캡처를 확인했다. 시스템 검사, 마이그레이션 누락 검사와 diff 공백 검사도 시행했다.

## 운영 반영

아직 배포하지 않았다. 다음 배포 시 검증된 DB 백업 뒤 컨테이너에서 `migrate`, `seed_fishing`을 실행해야 한다. 신규 테이블은 `0008_fishing_cast`와 `0009_herb_harvest`다. `seed_fishing`은 낚시·채집 물품 세 개와 낚시꾼·약재상 상점이 없을 때만 추가한다. 기존 가격·출판 여부·봇짐·엽전은 덮어쓰지 않는다. 이전 213 작업의 경복궁/성당 장면 데이터 업데이트 묶음도 아직 운영 적용 전이다.

다운로드 작업의 `docs/aks_objects_manifest.json`, `docs/aks_objects_catalog.csv` 변경은 별도 작업이므로 이 커밋에서 제외한다.
