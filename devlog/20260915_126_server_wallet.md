# 126 — 엽전 표시와 서버에 기록하는 잔고

사용자 요청: 내가 돈이 얼마나 있는지 보여 주기, 잔고는 서버에 기록하기(클라이언트에 두면 조작한다).

## 문제

125의 가게는 엽전과 봇짐을 브라우저 `localStorage`에 두고 브라우저가 가격을 계산했다. 개발자 도구로 값을 고치면 끝이다. 이 버전(v0.3.5 이미지)은 배포하지 않았다.

## 서버가 기록하고 판단

- 모델 `Player`(익명 토큰, 엽전), `PlayerItem`(봇짐), `Trade`(거래 기록), migration `0002_player_economy`.
- `webapp/economy.py`: 서명된 HttpOnly 쿠키로 플레이어를 찾고, 없거나 서명이 틀리면 새 플레이어(처음 엽전 3000문)를 만든다. 거래는 서버의 `npcs.json` 가격·가게 품목만 쓰고, 가게가 파는 물건인지, 수량 1~99, 엽전·봇짐이 충분한지를 트랜잭션 안에서 확인해 반영하며 거래 기록을 남긴다. 플레이어별로 1초에 5건까지.
- API: `GET /api/player/`(엽전·봇짐, CSRF 쿠키 설정), `POST /api/shop/trade`(CSRF 필수). 3D 화면에도 CSRF 쿠키를 붙인다.
- 백오피스: 플레이어와 거래 기록을 읽기 전용으로 볼 수 있다(추가·수정·삭제 불가).

## 화면

- 지도 위쪽 가운데(좁은 화면은 왼쪽 아래)에 늘 보이는 엽전 표시. 페이지를 열 때와 거래할 때마다 서버 값으로 갱신한다.
- 가게 창은 사기·팔기를 서버에 요청하고 서버가 돌려준 엽전·봇짐과 안내문을 그대로 보여 준다. `localStorage` 저장은 없앴다.

## 한계

- 계정이 없어 플레이어는 브라우저 쿠키 단위다. 쿠키를 지우면 새 플레이어가 되지만, 사람끼리 주고받는 경제가 없어 이득이 없다. 계정이 생기면 플레이어를 계정에 묶는다.
- 가게 위치에 실제로 서 있는지는 서버가 알 수 없어 확인하지 않는다.

## 검사

- Django 39개 통과. 새 `webapp/test_economy.py`: 쿠키·플레이어 생성과 위조 쿠키, CSRF 없는 거래 403, 요청에 넣은 가격 무시하고 서버 가격으로 사고팔기, 다른 가게 물건·없는 가게·없는 물건·수량 0/100/문자열·잘못된 거래 종류·없는 물건 팔기·엽전 부족이 모두 거절되고 아무것도 바뀌지 않음, 1초 6번째 거래 429.

## 배포

- dolfinid에 웹 v0.3.6 배포(`bash deploy.sh v0.3.6 v0.3.4`, 멀티플레이 v0.3.4 유지). migration `0002_player_economy` 적용, `sync_content` 변경 0, `healthcheck.py --deploy` 통과. Nginx 사이트 설정 변경 없음.
- 124에서 고친 `deploy.sh`로 처음 배포해, 배포 직전 검증 스냅샷 `backups/content/pre-deploy/content_v0.3.6_20260915_133036.sqlite3`가 실제로 만들어진 것을 확인했다.
- 웹 digest `sha256:75bc6f8b7c174d4f7a4f3bdb5bfb3c5253ebf28f22ee03a8203c640dc74a1b44`.
- 운영 확인(HTTPS, 브라우저와 같은 쿠키·CSRF 흐름): 새 플레이어 3000문, CSRF 없는 거래 403, 요청에 가격 1을 넣은 무명 사기가 서버 가격 250문으로 처리(2750문), 되팔기 2900문, 플레이어 쿠키 발급, 공개 `/healthz` 정상. 이 확인으로 운영 DB에 시험 플레이어 1명과 거래 기록 2건이 남았다.
- 시작 엽전은 3000문(30냥)으로 둔다. 돈을 버는 방법은 뒤에 만든다(사용자 의견: 심부름부터).
