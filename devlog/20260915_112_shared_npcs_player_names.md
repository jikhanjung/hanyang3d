# 112 — NPC 동기화와 첫 걷기 이름 입력

사용자 요청: NPC 움직임도 공유하고, 처음 1인칭으로 들어갈 때 이름을 입력받아 머리 위에 표시한다. 이후 캐릭터 커스터마이즈를 고려하며, 현재 이름 저장 위치도 설명했다.

## 구현

- 기존 보행 경로 생성·왕복 이동·회피 계산을 렌더러 없는 공통 모듈 `walking_simulation.js`로 분리했다. 혼자 보는 지도는 같은 모듈로 로컬 시뮬레이션을 유지한다.
- Colyseus가 보행자 130명에 `경로ID:번호`를 부여하고 초당 10회 이동·회피를 계산한다. 주변 NPC뿐 아니라 공간 내 모든 접속자의 위치를 회피 계산에 반영한다.
- 서버는 원도 배치 TPS와 고도 범위 메타데이터로 브라우저의 Float32 원도 격자·삼각형 보간을 재현한다. 경로 좌표 키가 일치하지 않는 브라우저는 접속시키지 않는다. 고도 래스터와 Three.js 렌더러는 서버에 필요 없다.
- 브라우저는 서버 NPC 스냅샷을 보간해 기존 InstancedMesh 위치를 갱신한다. 개인의 보행 재생·표시 설정은 서버 시간을 멈추지 않는다. 퇴장하면 해당 시점에서 로컬 재생으로 돌아간다.
- 궁감과 훈련 군사의 정해진 동작은 서버 공통 시간으로 재생한다. 최종 프레임 루프에서 누락돼 있던 이들의 갱신을 연결했고, 궁감의 정지 중 방향도 이전 프레임에 의존하지 않도록 했다.
- 처음 걷기에 진입하면 이름 입력 대화상자를 연다. 취소하면 진입하지 않고, 유효한 이름은 브라우저 localStorage에 기억한다. 1~16자 검사와 정규화를 클라이언트·서버에서 공통으로 적용한다.
- Colyseus는 접속 ID에 검증한 이름을 연결하며 위치 메시지로 이름이나 ID를 바꿀 수 없다. 자신의 3인칭 캐릭터와 다른 접속자의 머리 위에 같은 이름표 모듈을 사용한다. 이름표 폭은 글자 길이에 맞춘다.

## 검증

- Django 15개 검사 통과.
- Node 직접 실행 검사 4개: 좌표 입력, 이름 정규화, 여러 플레이어를 피하는 NPC 계산, 지도 경로 로드와 NPC 130명.
- 실제 Colyseus 연결 검사: 이름 전달, 잘못된 이름·경로 키 거부, 같은 틱의 NPC 상태 일치, 클라이언트 애니메이션 없이 서버 시간 진행, 기존 이동·퇴장·버전 분리 통과.
- 독립 브라우저 2개: 이름 입력 취소·형식 검사, 이름표, 동일 NPC 스냅샷, 개인 설정과 무관한 서버 시간 진행, 이동·방향·퇴장·재접속·탭 종료 통과.
- 기존 보행 충돌 검사: 건물 진입 차단, 1인칭 클릭, 보행자 회피·간격, 건물 이름·LoD 통과.
- 모바일 실제 터치 검사: 이름 입력창, 멀티터치, 포커스, 입력 취소, 재진입, 키보드 이동 통과. 화면 검토에서 입력 필드의 기존 전역 max-width 제한과 과도하게 넓은 이름표를 발견해 수정했다.

## 저장과 남은 범위

이름은 브라우저 localStorage와 접속 중 Colyseus 메모리에 있으며 DB는 없다. 동일 이름을 여러 사람이 사용할 수 있고, 계정 인증이나 소유권을 뜻하지 않는다. 이후 영구 캐릭터 ID·이름·외형은 Django DB에 저장하고 Colyseus가 접속 시 불러오는 방향을 설명했다. 커스터마이즈와 계정 저장 자체는 이번 범위가 아니다.

플레이어의 이동·지형 충돌은 여전히 브라우저 판정이다. NPC의 권위 있는 상태를 공유하지만 전투·거래까지 검증하는 게임 서버는 아니다. 네트워크 지연·보간에 따른 순간적인 화면 차이는 남으며 동시접속 부하 시험과 운영 배포는 수행하지 않았다.
