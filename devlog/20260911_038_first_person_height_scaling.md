# 038 — 높이 강조를 두 번 적용하던 1인칭 시점 수정

**날짜**: 2026-09-11\
**선행**: [033 1인칭 시점](20260911_033_first_person.md), [036 검증 한계](20260911_036_from_city_overview_to_street_walk.md)

사용자가 1인칭에서 높이를 1.5배나 2배로 강조하면 하늘 높이 떠오른다고 알려 주었다.

## 이미 늘어난 지형 높이에 다시 배율을 곱했다

높이 선택을 바꾸면 지형과 원도 메시의 정점 높이가 `원래 높이 × 배율`로 갱신된다. `cityWall.supportAt()`의 공간 인덱스는 이 정점 배열을 참조하므로, 1인칭에서 조회하는 값도 이미 배율이 적용된 높이다.

그런데 `groundAt()`에서 이 값에 배율을 다시 곱하고 있었다. 원래 지면이 50 m라면 2배 지형의 표면은 100 m인데 카메라는 201.65 m에 놓이는 식이다. 눈높이 상수 1.65 m를 잘못 정한 것이 아니라 기준 지면을 두 번 늘린 오류였다.

조회한 표면 높이를 그대로 사용하도록 중복 곱셈을 제거했다. 고도 배율이나 원도 불투명도를 바꾼 직후에도 `firstPerson.update(0)`을 호출해 다음 이동 입력을 기다리지 않고 눈높이와 이동 기준 지면을 맞춘다.

## 기존 검사가 오류를 놓친 이유

기존 검사는 `camera.y - firstPerson.ground == 1.65`인지 확인했다. 카메라와 검사에 쓰인 지면이 같은 잘못된 계산을 공유했기 때문에, 실제 지형과 떨어져 있어도 통과했다.

[브라우저 검사](../scripts/terrain/check_first_person_browser.py)에 별도의 수직 광선 교차 검사를 추가했다. 실제 표시 중인 DEM·원도 메시를 위에서 아래로 교차해 표면 높이를 구하고 카메라와의 차이를 직접 비교한다. 보행 계산은 작은 바닥 범위의 최고값을 쓰고 광선은 중심점을 검사하므로 8 cm 이내 차이를 허용한다.

검사 범위는 1 → 1.5 → 2 → 1배 전환, 2배에서 원도 숨김·복원과 하천 보정 전환, 이미 강조한 상태에서 1인칭 재진입이다. 기존 이동·드래그 시선·미니맵·나침반·전체 지도 복귀 검사도 유지한다.

이 수정은 DEM·원도 높이의 중복 강조를 해결한다. 옛길의 별도 표시 오프셋, 교량 상판이나 건물 충돌까지 포함한 보행 표면 판정은 별도 작업이다.

## 확인 결과

브라우저 검사를 통과했다. 수직 광선으로 구한 실제 표면과 카메라 사이의 높이는 원도 표시 상태에서 1배 1.6532 m, 1.5배 1.6548 m, 2배 1.6564 m였다. 원도를 숨긴 2배에서는 1.6504 m였고 하천 보정 전환과 재진입 후에도 유지됐다. 기존 이동 거리는 2초에 약 3 m, 시점 복귀·드래그·길잡이 검사도 통과했으며 JavaScript 오류는 없었다. Django 7개 검사도 통과했다.
