# 123 — Git 콘텐츠 변경을 운영 DB로 반영(sync_content)과 이야기·자료집 보완

[120](20260915_120_codex_review.md) 검토의 수정 3단계(콘텐츠).

## 문제

v0.3.0부터 운영 콘텐츠의 정본은 DB인데 `import_content`는 빈 DB에서 한 번만 돈다. 그 뒤 Git의 `1750_landmarks.json`·`doseong_stories.json`을 고쳐도 운영에 반영될 길이 없고, 테스트·브라우저 검사는 JSON을 보므로 통과해 아무도 모른다.

## `manage.py sync_content` (`webapp/content_sync.py`)

- 건물과 이야기마다 공개 필드(이름·분류·설명, 배치 설정, 모형, 이야기 대상·본문, 출처)의 지문을 만들고, 마지막 동기화 때의 지문을 `ContentImport(content-sync-v1)`에 둔다.
- Git만 바뀌었으면 DB를 갱신, 운영(백오피스)만 바뀌었으면 유지, 둘 다 바뀌었으면 충돌로 보고만 한다. Git에 새로 생긴 항목은 추가하고, 동기화 뒤 운영에서 지운 항목은 되살리지 않는다. DB에만 있는 항목은 보고만 한다.
- 첫 동기화 전에는 지문이 없으므로, 가져온 뒤 한 번도 저장되지 않은 행(`updated_at` ≤ 가져온 시각)을 편집되지 않은 것으로 본다.
- 기본은 미리보기(트랜잭션 되돌림), `--apply`로 저장. `docs/landmarks.md` 안내 문단은 차이 수만 보고한다.
- DB 모드 `deploy.sh`는 가져오기 뒤 `sync_content --apply`를 실행한다(명령이 없는 옛 이미지에서는 건너뜀). 배포 전 DB 검증 백업은 그대로 먼저 한다.

## 이야기 보완 (117의 새 이야기, 실록 대조 결과)

- 종묘 대리청정: 전교가 든 뜻을 ‘왕의 건강’이 아니라 쌓인 병과 오래 품은 물러나려는 뜻, 나랏일이 밀리지 않게, 세자의 정치 수련으로 고쳤다.
- 홍화문 군역: 참석자 대부분이 호포를 편하다고 답한 사실을 넣고, 균역법으로 이어졌다는 연결의 출처로 영조실록 26년 7월 2일 제3기사(양역 절목)를 더했다.
- 흥인지문 부역민: 2월 20일 기사에는 ‘준천’이라는 말이 없으므로, 준천소에 쌀과 감곽을 내려 역군을 먹이게 한 2월 19일 제1기사를 출처로 더하고 본문에 준천 공사 중이었음을 밝혔다.

## 자료집 (`docs/joseon_major_events.md`)

- 각주 59: 링크 이름을 실제 기사 제목으로 고치고, 준천 공역임을 보여 주는 2월 19일 기사를 함께 달았다.
- H21: ‘공역에 참여한 주민’을 기사대로 자원한 제주 사람·공인, 부역에 온 도성 주민, 집이 헐린 냇가 주민으로 나눠 적었다.

## 검사

- Django 32개 통과. 새 `SyncTests`: 첫 동기화가 깨끗하고 미리보기는 아무것도 저장하지 않음, Git만 바뀐 이야기·건물 배치 갱신과 출처 교체, 운영에서 고친 행은 충돌로 남음, 이후 Git 수정은 반영되고 운영만 고친 설명은 유지, 새 이야기 추가, 운영에서 지운 이야기 유지.
