## 카탈로그와 상세 페이지 보존

`sources.csv`에 우선 조사 후보 7건을 등록했다. 원문 조사에서 옮긴 후보이며 서지 검증 상태는 모두 `unverified`이다. 파일 취득 여부는 별도 `assets.csv`에서 관리한다.

사용자 요청에 따라 아카이브 번호·유물 번호·별도 자료 번호·시기 원문·자료출처·상세 메타데이터 경로·취득일을 추가했다. 상세 설명 전체와 원문 항목명은 로컬 JSON, 실제 페이지는 HTML로 보존하고 SHA-256을 기록한다.

`extract_seoul_archive.py`는 저장한 HTML의 상세 표를 추출하는 표준 라이브러리 기반 스크립트다. 레이아웃 공백만 정리하며 설명을 요약하지 않는다. 네트워크 수집이나 카탈로그 자동 갱신은 구현하지 않았다.

## 서울역사아카이브 다운로드 확인

사용자가 지정한 입력값:

- 개인: `kGubun=1`
- 기타: `kSubject=U99`
- 상세목적: `kDescr=조선시대 한양 모습 탐구`

상세 페이지의 실제 폼을 확인하고 목적 제출 POST 후 다운로드 GET 순서로 도성대지도 1건을 취득했다. Referer 없는 첫 다운로드는 HTTP 200의 오류 HTML이었다. 상세 페이지 Referer를 포함한 재요청에서 정상 JPEG를 받았다. 목적 제출은 중복하지 않았다.

| 항목 | 확인 결과 |
|---|---|
| 사료 / 파일 ID | src-0001 / asset-0001 |
| 아카이브 번호 | srd-415196 |
| 유물번호 | 서14165 |
| 파일 | JPEG, 3124 × 2743 pixel, 2,836,782 bytes |
| 이용 조건 표시 | 상세 페이지의 공공누리 제1유형(출처표시) |
| SHA-256 | f5b791653d008346d9eaa5dc612e498175f28f6ecf579d1c56c7082df36267f0 |

현재 JPG는 전체 구조 참고용이다. 세부 판독 적합성이나 최고 해상도 여부는 확인하지 않았다. 작은 지명·골목을 판독하기 어려우면 미판독으로 남기고 필요한 구역의 부분도 또는 고해상도 원본을 후속 조사한다.

## 검증

- 로컬 Markdown 링크의 대상 존재 여부 확인.
- 카탈로그 CSV 열 수·중복 ID 확인.
- JPG 파일 형식·해상도·크기·SHA-256 확인.
- 상세 표 7개 항목, 식별자, 설명 끝부분, 빈 장소 필드 추출 확인.
- 오류 HTML을 상세 페이지로 받아들이지 않는지 확인.
- 스크립트 CLI 도움말 실행 및 `git diff --check` 확인.
- 원본 디렉터리의 파일은 Git 제외, 카탈로그와 `.gitkeep`은 포함되는지 확인.

브라우저 UI 자동화, 대량 수집, GIS 정합, 3D 생성, 뷰어 실행은 수행하지 않았다.
